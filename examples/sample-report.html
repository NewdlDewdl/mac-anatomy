  How firmlinks work:
    The Signed System Volume mounts read-only at /. The user-data volume
    mounts at /System/Volumes/Data. A firmlink is a per-path "this name
    on the SSV is actually this directory on Data" mapping. When you
    read /Applications, the kernel transparently redirects to
    /System/Volumes/Data/Applications. This is why /Applications stays
    writable despite / itself being sealed.

    Unlike symlinks, firmlinks don't show up in `ls -l` and don't appear
    in path resolution traces — they're a kernel-level bind, set once at
    boot from /usr/share/firmlinks.

SIP

  System Integrity Protection status: enabled.

  SIP protects:
    • Filesystem  /System, /usr (except /usr/local), /bin, /sbin, parts
                  of /Applications. Even uid 0 cannot write or delete.
    • NVRAM       Restricted variables — boot-args is the famous one.
    • Kexts       Only Apple-signed (or user-approved system-extension-
                  whitelisted) kernel extensions can load.
    • Debugging   Apple system processes refuse ptrace/dtrace attach.
    • Tasks       sudo, fs_usage, opensnoop refuse to inspect Apple procs.

  To disable (rarely warranted, breaks many security guarantees):
      1. Boot to Recovery: Apple Silicon → power-hold; Intel → Cmd-R.
      2. Open Terminal in Recovery.
      3. csrutil disable
      4. Reboot.

  Disabling SIP on Apple Silicon also turns off Authenticated Root for
  the SSV, so a snapshot/seal mismatch becomes possible and the boot
  chain will print a warning. To restore: re-boot to Recovery, run
  `csrutil enable`, reboot.
